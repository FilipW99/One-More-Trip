# Handover

Status as of 2026-11-22: the first playable build of One More Trip is on `main`, merged in PR #1. This document is the starting point for whoever picks the project up next.

## What it is

One More Trip is a short-run roguelike with tick-based combat and long-term meta progression, built from Filip's design doc, `meta-progression.md`. It is a TypeScript + Vite browser game with no backend. Saves live in localStorage.

A trip goes like this:

1. Pick one of 3 character slots and a combat focus (melee, ranged or magic). The focus sets the starting kit.
2. Travel through four acts. Each act is a branching map of combat, elite, rest, Slayer master, trader, chest, gathering and sea-route rooms, ending in a boss.
3. Fight on a 0.6 s tick, switching protection prayers when attacks are telegraphed.
4. After each act boss, retreat or press on.
5. Bring XP home. Spend skill points (24 tracks, 10 ranks each), upgrade the hub, unlock Relics, opt into Omens, and take one more trip.

## Placeholders and real content

The parts of Filip's design that come from the source game (bosses, locations, monsters, items, prayers, spells, relics, pets, system names and art) are currently filled with generic placeholders. They are the swap points for Filip's real content.

- Every placeholder record has `ph: ph('§x', 'slot')` naming the design-doc slot it fills. The UI shows a purple **PH** badge next to it (it can be hidden in Settings).
- [PLACEHOLDERS.md](PLACEHOLDERS.md) lists all 290, with file and line. It is generated by `npm run placeholders`, and `npm run check` fails if it's out of date.
- [REPLACING_CONTENT.md](REPLACING_CONTENT.md) explains the swap: edit the record in `src/content/`, set `ph: null`, and map art files in `public/assets/` through asset keys in `manifest.json`.
- All content lives in `src/content/` as data, and the engine never hard-codes content names, so swapping content doesn't need engine changes.

## Run and test

```sh
npm install
npm run dev            # http://localhost:5173
npm test               # 37 Vitest unit tests (~3 s)
npm run typecheck
npm run check          # typecheck + unit tests + placeholder report up to date
npm run e2e            # Playwright smoke test: builds, then plays a trip in Chromium (~20 s)
npm run sim            # balance simulator: 100 trips per profile, prints XP and death stats
npm run sim -- 60 progress   # 60 trips with one new melee character, prints levelling pace
npm run build          # static site in dist/
```

URL parameters for testing: `?seed=123` fixes the trip seed and `?tick=60` speeds up combat. `window.__omt` is the app instance and `window.__omtCombat` is the live fight.

There is no CI yet. Run `npm run check` and `npm run e2e` before merging.

## Code map

See [ARCHITECTURE.md](ARCHITECTURE.md) for the full picture. The short version:

| Path | What |
|---|---|
| `src/config.ts` | All tuning numbers: XP curve, drop rates, costs, tick length, boon thresholds |
| `src/content/` | Game data: `items.ts`, `monsters.ts`, `bosses.ts`, `acts.ts`, `prayers.ts`, `powers.ts` (relics, omens, boons), `hub.ts`, `skills.ts`, `terms.ts`, `assets.ts`. Schema is in `types.ts`, and `index.ts` exposes everything as `C` |
| `src/core/state.ts`, `save.ts` | Save and run state shapes (plain JSON); create, load, validate, migrate |
| `src/core/mods.ts` | Folds every Effect (skills, hub, relics, omens, boons, prayers, item passives) into one `Mods` object |
| `src/core/combat/engine.ts` | Tick engine: player commands, monster and boss AI, projectiles, hazards, prayers. `formulas.ts` has hit chance and max hit, `geometry.ts` has pathing and line of sight |
| `src/core/run.ts` | Trip lifecycle: `startRun`, `enterNode`, `processKills`, `finishEncounter`, loot, boons, `continueToNextAct`, `retreat`, `endRun` |
| `src/core/rooms.ts` | Event rooms: rest, trader, chest, gathering, Slayer, sea |
| `src/core/hub.ts` | Between-trip actions: upgrades, skills, respec, relics, omens |
| `src/core/mapgen.ts`, `loot.ts`, `encounters.ts` | Act maps, drop pools, fight composition |
| `src/core/inventory.ts`, `progression.ts`, `stats.ts`, `rng.ts` | Equip rules, XP curve and levels, derived combat stats, seeded RNG |
| `src/core/bot.ts` | Autoplayer used by the simulator and tests |
| `src/render/` | `placeholders.ts` draws the procedural art and loads overrides; `arena.ts` is the canvas combat renderer |
| `src/ui/` | `app.ts` (navigation, save, modals) and `screens/` (title, hub, run, combat, results) |
| `tests/` | Unit tests (`*.test.ts`) and `e2e/smoke.spec.ts` |

### Things worth knowing before changing code

- **Core has no DOM.** Everything in `src/core` runs headless, which is how tests and the simulator work. UI code reads state and calls core functions.
- **Effects vocabulary.** Bonuses are `{ mod }`, `{ flag }`, `{ gate }`, `{ weight }` or `{ room }` entries. Rules call `mod(m, 'key')` or `m.flags.has('flag')` rather than checking where a bonus came from. A new flag needs an entry in `src/core/flags.ts`; a test enforces this.
- **Seeded RNG.** The generator state is stored in the run (`run.rng`) and used through `withRng`. Use it for anything random in a trip, so trips stay reproducible.
- **Tick order** (`stepEncounter`): timers, heal over time, player move, player attack, monsters act, projectiles land, hazards land, prayer drain, special and run energy, then the win or loss check. Player input only queues commands between ticks. Protection prayers are checked when an attack lands, not when it starts.
- **Saves.** The `SAVE_VERSION` and `migrate()` hook are in `src/core/save.ts`. Bump the version and migrate if you change saved shapes.
- **Fights are not saved.** The `Encounter` lives in memory. After a reload mid-fight, that room's fight restarts with current HP and supplies.

## Decisions

[DECISIONS.md](DECISIONS.md) has the defaults chosen for the design doc's open questions (§10) and the rules filled in where the doc was silent:

- Items are lost at the end of a trip except Vault slots (0 to 3).
- Any character can equip any item that meets its level requirement.
- The boss-unique pity counter is on.
- Level cap 60 with 65 points; respec as in §4.1; 0.6 s tick.
- The tomb raid is the finale (act 4). The volcanic route swaps act 3 for a wave gauntlet and unlocks with the Portal Chamber.

Filip hasn't confirmed these yet. They're all config or content values, listed with where to change each.

## Balance

This is a first pass, measured with `npm run sim` (60 trips per profile; the bot reacts correctly to 85% of attacks). Compared with the design doc's §8.2 targets:

| Outcome | Measured | Target |
|---|---|---|
| Died in act 1 | 260 to 350 XP | 300 to 500 |
| Died in act 2 | 520 to 850 XP | 800 to 1,200 |
| Full clear | 2,150 to 2,300 XP | 2,000 to 2,800 |

So act 1 deaths sit at the low end, act 2 deaths by low-level characters fall short, and clears are on target. The autoplayer reaches level 30 in about 7 trips and level 60 in about 32. The targets are 8 to 10 and 40 to 50, but people die more than the bot. The main walls for mid-level characters are the act 2 bosses and the act 3 boss, and levels 30 to 45 rarely clear (2% at level 30, 17% at level 45). DECISIONS.md has the full table. `npm run sim -- 60 sweep --deaths` shows where each profile dies. Profiles are defined at the top of `scripts/simulate.ts`.

## Known gaps

- **No CI.** Nothing runs on PRs.
- **Mid-fight saves.** Reloading restarts the fight, which can also be used to escape a losing fight.
- **Art and audio.** Art is procedural shapes until real assets are mapped. There is no sound at all.
- **Hub features with no screen.** The Trophy room tier ("display your boss trophies") has no UI yet. Pets are cosmetic only: the active pet follows you in fights.
- **Mobile.** There is one narrow-screen breakpoint (900 px), but nothing has been tested on touch devices. Combat leans on hotkeys (prayers, R run, S special, P pause).
- **Onboarding.** There's no tutorial beyond the "How a trip works" panel on the hub.
- **Bot vs. players.** The autoplayer never retreats, so simulated Coin income (and hub pacing) is lower than a careful player's.
- **Code smells.**
  - `src/core/rooms.ts` and `src/core/run.ts` import each other (only at call time).
  - `effectsText` in `src/ui/screens/hub.ts` is unused.
  - Screens rebuild their DOM on most actions. That's fine at this size, but worth keeping in mind before adding heavy panels.

## Suggested next steps

1. **Add CI**: a GitHub Actions workflow running `npm ci`, `npm run check` and `npm run e2e`.
2. **Play-test and tune.** Have Filip play a few trips per focus, then adjust the act 2 and act 3 bosses (`src/content/bosses.ts`) and monster stats, checking with `npm run sim`.
3. **Settle the open questions** in DECISIONS.md with Filip and update config to match.
4. **Save fights mid-way.** Serialize the `Encounter` into the run, or decide that a reload counts as a retreat or a death.
5. **Build the Trophy room** and a boss kill-count view; these fit naturally in the hub.
6. **Do an art pass** through `public/assets/manifest.json`, once Filip supplies assets. Add sound hooks using the same asset-key pattern.
7. **Swap in the real content**: follow REPLACING_CONTENT.md, set `ph: null` on each replaced record, and regenerate PLACEHOLDERS.md.
